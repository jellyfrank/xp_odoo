# 第九章 报表

Odoo 中的“报表”有两类含义：一类是打印给客户或内部使用的 PDF 单据，另一类是系统中的统计分析报表。

自主实施时，先把标准报表用起来，再判断哪些报表真的需要定制。

## 两类报表

| 类型 | 示例 | 用途 |
| --- | --- | --- |
| 打印报表 | 报价单、销售订单、发票、送货单、采购订单 | 对外发送或内部归档 |
| 分析报表 | 销售分析、库存分析、应收账款、采购统计 | 管理决策和日常检查 |

不要把所有 Excel 都理解成“必须定制报表”。很多统计可以通过列表、筛选、分组、透视表和导出完成。

## 文档布局

文档布局决定 PDF 单据的外观，例如报价单和发票的 Logo、颜色、页眉、页脚。

可以从 **设置 -> 一般设置 -> 公司 -> 文档布局** 设置。

![文档布局设置](images/basic-cn-report-layout-settings.png)

上线前建议确认：

- Logo 是否清楚；
- 公司名称、地址、电话、邮箱是否正确；
- 单据颜色是否适合公司品牌；
- 页脚信息是否正确；
- 中英文显示是否正常；
- 报价单、发票、送货单打印后是否可读。

文档布局是全局基础设置，不建议每天改。

## 常见打印报表

不同模块会有自己的打印报表。

| 模块 | 常见报表 |
| --- | --- |
| 销售 | 报价单、销售订单 |
| 采购 | 采购订单、询价单 |
| 库存 | 送货单、收货单、拣货单、库存标签 |
| 财务 | 客户发票、供应商账单、付款收据、账龄报表 |
| POS | 小票、交班报表 |
| 生产 | 生产订单、工单、物料清单 |

第一次上线时，建议优先检查最常用的 3 到 5 张单据，不要一开始就要求所有报表完全按旧系统重做。

## 分析报表

Odoo 的很多列表都支持筛选、分组和导出。部分模块还有图表、透视表和仪表板。

常见分析问题：

- 本月销售额是多少；
- 哪个销售员业绩最好；
- 哪些客户应收超期；
- 哪些产品库存不足；
- 哪些供应商采购金额最高；
- 哪些订单还没发货；
- 哪些发票还没付款。

这些问题很多可以通过原生筛选和分组解决，不一定需要开发报表。

## 筛选、分组和收藏

使用报表前，先学会三个动作：

| 功能 | 用途 |
| --- | --- |
| 筛选 | 只看符合条件的数据，例如本月订单 |
| 分组 | 按客户、销售员、状态、日期汇总 |
| 收藏 | 保存常用查询条件，下次快速打开 |

很多客户以为自己要“定制报表”，其实只是缺一个保存好的筛选条件。

## 导出到 Excel

Odoo 支持从列表导出数据到 Excel 或 CSV。

适合导出的场景：

- 临时分析；
- 给外部人员查看；
- 和旧系统对比；
- 财务核对；
- 批量检查基础数据。

不建议长期依赖导出做日常管理。如果每天都要导出同一张表再手工加工，说明流程或报表设计需要优化。

## 报表口径

报表最重要的不是样式，而是口径。

例如“销售额”可能有不同含义：

- 报价金额；
- 已确认销售订单金额；
- 已开票金额；
- 已收款金额；
- 不含税金额；
- 含税金额；
- 按订单日期；
- 按发票日期；
- 按收款日期。

如果不先定义口径，开发出来的报表也会被认为“不准”。

上线前要让老板、销售、财务确认关键指标口径。

## 什么时候用原生报表

适合原生报表：

- 标准报价单和发票；
- 销售、采购、库存基础统计；
- 应收应付和账龄；
- 常规筛选和分组；
- 管理者临时查看数据；
- 第一阶段上线验收。

原生报表的优点是稳定、维护成本低、升级风险小。

## 什么时候需要定制报表

以下情况可以考虑定制：

- 客户有固定格式要求；
- 政府、海关、平台要求特定格式；
- 老板需要跨模块管理驾驶舱；
- 原生字段无法满足统计口径；
- 需要复杂计算，例如返利、佣金、毛利分摊；
- 需要对接外部 BI 或数据仓库；
- PDF 单据必须符合行业版式。

定制前要先确认：

| 问题 | 说明 |
| --- | --- |
| 谁看 | 老板、财务、销售、仓库还是客户 |
| 看什么 | 指标和字段 |
| 怎么算 | 统计口径 |
| 多久看 | 实时、每日、每月 |
| 数据来源 | 销售、库存、财务还是外部系统 |
| 输出形式 | PDF、Excel、图表、仪表板 |

没有口径的报表需求，不建议立即开发。

## 报表验收清单

| 检查项 | 通过标准 |
| --- | --- |
| 文档布局 | Logo、地址、电话、页脚正确 |
| 报价单 | 客户、产品、价格、税率显示正确 |
| 发票 | 金额、税额、付款信息正确 |
| 送货单 | 产品、数量、地址正确 |
| 分析报表 | 销售、库存、应收等口径已确认 |
| 导出 | 关键列表可以按需要导出 |
| 权限 | 普通员工不能看到不该看的报表 |
| 定制需求 | 已区分原生可做和需要开发的部分 |

报表不是越多越好。第一期最重要的是让关键岗位看到自己需要的数据，让老板和财务认可核心指标口径。

## 按客户使用不同报表样式

标准 Odoo 通常按公司配置文档布局。第一期这样做最稳。但在一些项目中，客户会希望同一个公司下，对不同客户打印不同的报表样式、公司标语、页眉页脚或特殊条款。

这类需求通常属于报表增强或定制范围。

在欧姆网络基础解决方案中，可以通过自定义报表配置实现更细的报表样式控制。

首先，可以在用户设置中开启自定义报表配置权限。

![开启自定义报表配置](./images/report1.png)

开启后，可以在技术设置中创建自定义报表配置。

![自定义报表配置](./images/report2.png)

然后在客户资料中指定该客户使用的报表配置。

![客户报表配置](./images/report3.png)

打印该客户单据时，就可以使用指定样式。

![自定义报表效果](./images/report4.png)

这种方案适合：

- 一个公司服务多个品牌客户；
- 不同客户要求不同页脚或条款；
- 外贸客户需要不同语言和风格；
- 集团公司需要统一系统但差异化对外文件；
- 代理商、渠道客户要求专用单据格式。

实施建议：先用原生报表跑通流程，再把确实有价值的客户差异报表做成配置或定制，不要一开始为所有客户都做单独报表。
